## Permitted rewrites

A rewrite changes how an expression is computed, never what it denotes. Two families: reach, which narrows a split search, and the value-cut collapse, which compacts a single-digit cut.

### Reach -- the bound read off the expression

A factor wears no face longer than its expression reaches, so a split search offers it no longer piece: the bound comes off the expression, never by streaming entries, and the matches are identical -- only the cuts tried are fewer. Reach is a single code point or range `1`, a literal its own length, a product the sum of its factors, and a closure `&` unbounded. `‸` marks the cut reach leaves.

| Query | On | Cut | Why |
| --- | --- | --- | --- |
| `{a..z}{0..9}` | `a5` | `a‸5` | each factor reaches 1 |
| `{cat}{0..9}` | `cat5` | `cat‸5` | `{cat}` reaches 3, pinning the head |
| `{{a..z,&{a..z}}}{\!}` | `hello!` | `hello‸!` | `{\!}` reaches 1, pinning the tail of the closure -- one probe, not six |

The bound is an upper one and only ever that: anything not priced exactly is priced *unbounded*, since over-approximating costs a probe and under-approximating drops a match. A subtraction is not priced at all -- stripping faces can only shorten the set. Where the pieces must cover the text *exactly* -- a product's own membership search, and the re-split a capture reads -- the bound is read from both ends: a cut leaving the factors after it more than they can spell between them can never be completed. A match covers a prefix and may end anywhere, so only the upper bound applies to the scan itself.

### Value-cut collapse -- a single-digit range cut is a range

Where value order and shortlex agree -- single-code-point digits -- a value cut of a contiguous span is itself a contiguous range, so the digit-walk collapses to a literal range. A cut that crosses into multi-digit numerals (`where aa..cc`) stays a walk.

| Expression | Rewrites to | Denotes |
| --- | --- | --- |
| `{a..z}[where c..g]` | `{c..g}` | c, d, e, f, g |
| `{0..9}[where 3..7]` | `{3..7}` | 3, 4, 5, 6, 7 |
| `{0..9}[below 3..7]` | `{3..6}` | 3, 4, 5, 6 |
| `{0..9}[where 7..3]` | `{}` | empty (hi below lo) |

The premise is *checked*, not assumed: the cut must stay inside single-digit numerals, every digit it takes must be one code point, and those must be adjacent code points in value order. A radix whose digits wear wider faces (`{a,bb}`) or that skips around the code space (`{a,c,e}`) fails the check and walks. The `below` row needs the whole program in hand rather than the cut alone, since L3 spells a top-exclusive cut as one cut less another (`{@lo..hi,!{@hi..hi}}`) and each half lowers on its own.

## Sentinel boundary

The surface declares a sentinel as one fresh face outside `char`, apart from every other sentinel (L1.5); everything concrete about that face is this contract's:

- **Allocation** -- the host assigns noncharacters from U+FDD0 up, in declaration order. Operational only: no denotation reads which code point a name drew, only that it sits outside `char` and apart from the rest.
- **Pool** -- Unicode holds 66 noncharacters, so a sixty-seventh declaration is refused: a finite pool outrun, kin to a budget (table below).
- **Ingest** -- a document that arrives spelling a noncharacter is refused (table below), which keeps the space engine-private.
- **Exit strip** -- at exit every declared sentinel's face is stripped from the document, so nothing engine-private ships and no cleanup statement has to be written.

## Refusals

The other half of the contract: where a read or a run cannot complete within a stated bound, it is refused with a diagnostic rather than left to hang or guess.

| Run | Refused when | Diagnostic |
| --- | --- | --- |
| membership in an unguarded closure -- `{a, &}` on a non-member | no stage settles it, so absence has no bound | `HimarkUnsettledError` |
| a canonical `$0` or factor `$k` read | the wearer sits past the read budget | `HimarkScopeError` |
| a value cut `@lo..hi` over an unbounded head | the radix exceeds the digit budget | `ValueLineError` |
| a match or a contracting pass | it spends past the host's work budget | `HimarkBudgetError` |
| a document at ingest | it spells a noncharacter (the sentinel space) | `HimarkSentinelError` |
| a `sentinel` declaration | the noncharacter pool (66) is exhausted | `HimarkSentinelError` |

A `<=>` that never reaches a fixpoint is the work budget's, not a row of its own: the iteration is one run, so the pass that would spin forever spends past the bound and is refused there. There is no measure to shrink -- L1.5's contraction carries none, and settling is the document ceasing to move.

Guarded and unguarded is the line the first row draws, and it is narrow on purpose. A `&` in a product is *guarded* when some sibling factor cannot spell the empty face, so every pass strictly lengthens and stage `len + 1` is exact; `{@x, &@x}` -- most of the standard library -- sits inside that fragment and decides absence as it always did. A bare `&`, or one whose siblings all admit the empty face, does not, and there the refusal falls. Having a factor beside the `&` is not the same as having a guard.

Which of these a port must reproduce differs. The unsettled refusal is semantic: an engine answering "absent" there is wrong rather than lenient, and `static/conformance/` pins it. The three budgets are not -- their *existence* is the contract and their size is the host's choice, so no case fixes a number.

> Finish line: the contract holds when every read and every match the surface admits either completes within a stated bound or is refused with a diagnostic -- never a hang, never a guess.
