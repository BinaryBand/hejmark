L1.5 is everything the host implements beyond denotation, and the one layer allowed to reject. Its admission rule is the floor's admission test read from above: a surface construct adds no denotation -- every application expands into the six constructors -- or it does not enter here; what refuses to expand goes to L1 as an axiom or nowhere. The floor never rejects, so rejection is this layer's whole job.

## Matching

- Query -- a universe run against text; it matches one entry, by any face. A query denoting the empty universe matches nothing; emptiness stays meaningless, not invalid.
- Capture -- the floor's `<value, face>` read off a hit. The object already carries the pair, so a capture is a binding, never a store; no operand holds a text field.
- Membership -- matching is set membership: does the text spell an entry? No value or ordinal semantics leak in; the matcher knows only spellings.
- Longest-first -- tile the text longest-face-first (maximal munch); where one face is a proper prefix of another, the longer wins. Declaration order never selects a match.
- Zero-width -- the unit's face is the empty spelling, and no match is ever accepted on it. The unit exists to be a factor (the product identity), not a query.
- Back-references -- the factor family stands in patterns too: inside a query, `{$k}` wherever a universe stands, or `$k` as a pipeline argument (`where 0..$2`), reads factor `k` of the same query -- strictly to its left, since only a bound factor can be read. The admission story is late-bound expansion: the matcher binds factors left to right, so by the time the reading factor is tried its read is bound, and substituting the face -- as it hit, the family's one reading -- turns every attempt into a plain floor query. Expansion parameterized by a binding, never new denotation. In a pattern position the face stands as the literal spelling it is; in an argument position it substitutes as a written argument, so the numeral binding rules apply unchanged -- canonicalization is what makes `where 0..$2` a value cut whatever padding the read hit wearing. A read never crosses a declaration: a `$k` in a `uni` or `:=` body stands in no query and is refused. Where a hit splits more than one way, the collision rule decides as ever (Emit, below), each split priced under its own bindings.
- Scope -- the matcher is total on queries whose closure bodies are all guarded: the settlement theorem decides a length-$L$ spelling by stage $L + 1$, and finite text offers only finitely many candidate lengths, whatever the order type above (closure-free queries were always in scope by the same finiteness). An unguarded or negative body still denotes -- the floor's totality -- but only semi-settles, so matching against it is out of scope: the diagnostic below, and this layer's one genuine residue.

## Names

- `uni name = {...}` -- a declaration; the name stands wherever a universe stands (member, factor, subtraction operand), contributing entry-wise by the floor's splice rule -- which is also what makes a name the way to union sub-universes without folding them, since splice spreads where a braced member quotients.
- Reference -- `@name` splices the declaration wherever a universe stands; the sigil is what keeps a name from ever reading as a spelling, so `{cat}` stays the literal face and `{@cat}` the splice. One namespace, resolved at expansion: the registers are its two reserved names -- bare `@` the head, `@0` its zero entry -- and numerals are not declarable, which is what keeps `@0` free.
- Acyclic -- a name may not reach itself through its declaration, directly or through other names. `&` is the language's only self-reference, and it lives on the floor; acyclicity is what keeps every expansion finite.

## Definitions

- Form -- `name params := body`, applied through the modifier pipeline `A[f x g y]`: stages left to right, each stage's result the next stage's operand.
- Substitution -- application replaces the body's parameters with the literal arguments and the operand token `_` with the stage operand; the result is an expression over names, registers, and the floor, and expansion continues until only constructors remain. `_` binds only at application: a definition invoked bare inside another body shares the caller's head (the registers' rule below) but receives no operand, so a `_` in its body is a scope error, never an inheritance. Definitions are non-recursive (recursion is the closure's) and acyclic like names, so expansion terminates.
- Head -- registers read the pipeline head, not the stage operand, and a definition invoked inside another body shares the caller's head: one radix rides the whole chain. `{0..9}[where 8..12 pad 1..2]` fills with `0` because the head is `{0..9}`, whatever `where` left in the pipe.
- Numeral parameters -- a parameter written as a numeral or numeral pair (`lo..hi`) binds canonicalized in the head radix: leading zero digits strip, so `aa` binds as `a` (value 0 either way). A lone numeral argument binds a pair parameter as the degenerate pair `n..n` -- the surface's echo of union's "a lone spelling is the singleton case", and already the floor's theorem, since `{2..2}` is `{2}` under the range compression -- so `pad 2` binds `w..w'` at `2..2`. Canonicalization and the degenerate pair are rules of binding, priced with the registers below.
- Exponent -- `A^n` is `A` written adjacent `n` times, iterated product running down to the identity: `A^0` is the unit, by the floor's product-identity theorem. The count is a decimal numeral on the page -- or a parameter that bound one, as `pad`'s `^{w'}` below -- never a value read in any universe: expansion counts, it never denotes, and a count that does not spell a decimal numeral is refused. Counting is the expander's arithmetic and refusal is this layer's privilege, which is what seats the notation here rather than on the floor's compression list; every application expands into iterated product, so the admission rule holds as written.

## Registers

- The in-language spellings of the expander's metafunctions -- the reads a written body needs that no expression can compute. The precedent is the floor's own bounded range: `{a..z}` = `{a.., !{s..}}` computes the successor `s` at expansion time; a register is the same move given a token, so that declarations, and not just spec prose, can lean on it.
- `@` -- the pipeline head itself, as a universe. The most primitive read there is: every register is a read of the head, and `@` is the head unread. It is what anchors the value line to the radix wherever a definition sits in the pipe. On an empty head it reads as the empty universe -- total, in the floor's manner.
- `@0` -- the zero entry of the pipeline head. Not derivable from `@`: no expression selects an entry by value, so the zero entry is its own read, not a cut of the head. On an empty head there is no zero entry and `@0` reads as the unit, so a fill built on it no-ops -- total, in the floor's manner.
- The inventory, closed: the shortlex successor (the floor's own, no token), numeral-parameter canonicalization and the degenerate pair (binding rules, no token), `@` and `@0` for the expander, and `$` and `$0` for the emitter with the factor family `$1..$n` addressing the hit's written factors -- read in a template (Emit, below) or standing in a pattern (Matching, above) -- priced on the same shelf. Four tokens and one addressed family in the language. A new register faces the scrutiny a new axiom does -- each is a hole in "the language writes its own std" -- and the finish line is measured by the inventory staying this size.

## Worked derivations

Transformation runs on three axes -- alphabet, value, face -- and none needs a primitive: each dissolves into the floor.

- Alphabet axis -- keeping and dropping entries are intersection and difference, on the floor's compression list.
- Value axis -- the closure generates the value line, so a value cut is a definition, not a primitive. `numerals` below is the canonical numerals of the head radix in value order: the zero digit first, then the closure's stages width by width, product order within a width already being value order. `where` cuts it with a spelling range: over a character radix, value order and shortlex agree on canonical numerals -- the floor's canonical-numerals theorem -- so the range cuts the value line exactly, and the order of the result is inherited from `numerals` through two subtractions. `where` never reads the pipe: it regenerates the value line from the head and cuts it -- a generator anchored to the radix, not a filter of its operand -- which is why its body carries no `_` and why it means the same thing at any stage.
- Face axis -- subtraction cuts it directly: the floor's subtraction acts on spellings, stripping the face that claims each one, and an entry drops only with its last face. A width cut is therefore a single subtraction of the unwanted widths -- not an idiom, let alone a primitive.

The std that the finish line asks for, written over this surface -- `C` is the code-point set as a bounded range minus the noncharacters (the sentinel space, below), the one `uni` the spec seeds:

```text
uni spellings   = {{{}}, &@C}                                 -- every spelling, in shortlex
fill            := {{{}, @0}}                                 -- one entry, faced empty and zero
nonzero         := {@, !{@0}}
numerals        := {@0, {@nonzero, &@}}                       -- the value line of the head radix
shorter w       := {@spellings, !{@C^w @spellings}}           -- widths below w
upto w          := {@shorter w, @C^w}                         -- widths at most w
longer w        := {@spellings, !{@upto w}}                   -- widths above w
where lo..hi    := {@numerals, !{@numerals, !{ {lo..hi} }}}   -- the value line cut by a spelling range
pad w..w'       := {@fill^{w'} _, !{@shorter w}, !{@longer w'}}
zeros           := {{{}}, &@0}                                 -- the zero-runs of the head, empty included
zfold           := {{@zeros}}                                  -- folded: one entry wearing every zero-run
padfree         := {@zfold _}                                  -- every entry at every zero-padding
```

`pad` is two face cuts: `fill^{w'}` gives every entry its faces from bare up to `w'` extra fills, and the subtractions strip every face too narrow or too wide, each entry surviving on whatever widths remain -- no arithmetic on `w'` needed, since the overshoot faces fall to `longer w'` regardless.

`zeros` through `padfree` are the uncapped pad: `pad` bounds its widths because `w'` feeds an exponent, and dropping the cap dissolves the exponent into a fold -- `zfold` is one entry of order type $1$, so the product `{@zfold _}` moves nothing on the value axis and hangs every zero-padding on the face axis. Matching a `padfree` result stays in scope, since membership decides it; a canonical read of one does not, since every entry wears infinitely many faces -- the read the bounded `pad` keeps.

| Expression                     | Denotes                             | Why                                                                                    |
| ------------------------------ | ----------------------------------- | -------------------------------------------------------------------------------------- |
| `{0..9}[where 8..12]`          | 8, 9, 10, 11, 12                    | `numerals` cut by `{8..12}`: width-1 digits from 8, width-2 canonicals to 12           |
| `{a..z}[where aa..cc]`         | a, ..., z, ba, ..., cc (55 entries) | `aa` binds canonical as `a`, so the width-1 numerals enter the range                   |
| `{8,9,10,11,12}[pad 2]`        | 88, 89, 10, 11, 12                  | `@0` is `8`; `shorter 2` strips the bare `8`, `9`; `longer 2` strips `810`, `888`, ... |
| `{0..9}[where 8..12 pad 1..2]` | {8,08}, {9,09}, 10, 11, 12          | head fills `0`; widths 1-2 both legal, so `8` keeps both faces; `010` is stripped      |

## Emit

Emit is the write half of using a universe against text, and it enters on the bar matching cleared: interpretation, not expression -- no template builds a universe the constructors do not reach, and every read it needs is priced as a register. Two objects and one join rule carry the whole section.

- Text objects and branches -- a **text object** is where spellings live: the document a statement runs against, or a string a template constructs. A **branch** is a span of one text object carrying the capture its match bound; the span (`[start, end]` to the host) and the floor's `<value, face>` are one datum seen twice, since the object's text over the span is exactly the bound face. Only branches cross `=>`: never a detached value, always a pointer into some text.
- Steps -- a statement is a chain of steps joined by `=>`, each a **query** (a universe expression, pipelines included) or a **template** (quoted `"..."`: literal text plus `{{...}}` interpolation sites, each holding one capture read). Arrows are top-level only: inside a brace or a quote, `=>` is literal text.
- Lines -- one declaration or statement per logical line: a brace or quote that spans physical lines stays one statement, a line whose first token is `=>` continues the statement above, blank lines separate nothing, and `//` comments run to end of line at brace depth 0 only, so `{http://x}` stays a face.
- A query step refines: it tiles the branch's text by the matcher above (whose scope rules it inherits), one sub-branch per match, and a query that matches nothing stops the branch -- the guard reading. Tiled matches are disjoint, so commits never contend and the splice needs no conflict clause.
- A template step constructs: it always builds a string, literal text landing as written and each interpolation rendering its read. An incoming branch anchors it -- the string commits over the branch's span, never rolled back, and each interpolation site continues as a sub-branch at its rendered span, carrying its read's binding, so decoration lands but never flows. A template with no interpolation site commits and ends its branch: nothing is left pointing anywhere. No incoming branch at all (a leading template) leaves the string detached: the rest of the chain computes over it and the document never changes.
- Bootstrap, without exception -- a leading query branches into the statement's target; a leading template is the detached string above. The whole-document rewrite is an idiom, not a case: `{@spellings} => "..."` tiles the entire text as one entry of `spellings`, maximal munch taking the longest face -- and on an empty document it does not fire, since the one face on offer is the empty spelling and zero-width never matches.
- Capture reads -- the emitter's registers, the match read as `@` is the head read: `$` is the hit as it hit, the bound entry at its bound face, and `$0` its canonical face -- the zero of the face axis, as `@0` is the zero of the value axis. The fold carries the transformation: an input spelling rides as a later face, the output as face 0, and no machinery beyond the floor's pair is needed.
- Factor reads -- `$1..$n`, one read per top-level factor, 1-based since `$0` is taken, being the canonical read. Adjacency is the product, so the hit binds one entry, and an entry of a product is a tuple: `$k` is component `k` of the bound tuple, spelled as it hit over its sub-span -- a pure read of a binding the match already carries. Where the hit's spelling splits more than one way across the factors, no new rule decides, because the floor's collision rule already has -- the spelling belongs to its least `<value, face>` claimant -- so `{a,ab}{c,bc}` against `abc` reads `$1` as `a` and `$2` as `bc`, the `(ab, c)` split having lost the spelling at the floor. Factors are the written units: an exponent's repetitions stay inside theirs, so `{a}^3{b}` offers `$1` and `$2`, the first reading all three repetitions. The reads are as-it-hit only -- no per-factor canonical read, exactly because a factor's entries may wear infinitely many faces, which matching tolerates and a canonical read would not. The price is `$0`'s: a split the text pins uniquely reads for free, and consulting the collision rule on an ambiguous one streams entries in value order -- iteration order, as ever -- refusing past the host's budget rather than guessing.
- Contraction -- `query <=>[@m] template` is the one iterated statement: the pass is the ordinary statement (tile, commit, splice), re-run until a pass finds nothing to rewrite. Admission is the settlement discipline stated as the dual it is: a guarded body settles because every stage lengthens a spelling, and a contracting statement settles because every pass strictly descends its measure -- the document before and after the pass, read as spellings of `@m`, the after strictly earlier in entry order. Iteration order is value order, as ever, and a well-order has no infinite descent, so the passes settle. The measure is an ordinary `uni`, named on the arrow -- declared, never inferred -- and the host checks each pass, not the rule: a pass that fails to shrink the measure is the diagnostic, and so is a document the measure does not spell. Two spellings of one entry sit nowhere earlier than each other, so a pass that only re-dresses an entry fails exactly as one that rewrites nothing. The comparison itself never streams: enumeration is member-major, windows sit in spelling order, products run leftmost-slowest and closures stage-major, so which of two spellings comes first is decided down the same structure the stream walks -- only an ambiguous split consults the collision rule, priced on the `$0` shelf. A falling count is a declarable measure too: a closure whose body adds one counted token per stage orders documents by their count, stage-major, so counting is stage order and needs no new machinery.
- Splice -- a statement's result is its committed strings laid over their spans with the text between kept, at every depth; the flat list with the spans dropped is the extraction view of the same result.

| -------------------------------- | ----------- | ------------ | ----------------------------------------------------------------------------- |
| `{{cat,feline}} => "{{$0}}"`     | `my feline` | `my cat`     | `feline` binds face 1; `$0` writes face 0                                     |
| `{a,e,i,o,u} => ""`              | `pattern`   | `pttrn`      | the empty string commits over each match                                      |
| `{@spellings} => "<b>{{$}}</b>"` | `abc`       | `<b>abc</b>` | one branch spans the whole text; decoration lands, `$` re-emits the hit       |
| `{a} => {b}`                     | `banana`    | `banana`     | a mid-chain query is a guard: no `b` inside an `a`-match, every branch stops  |
| `"seed" => {e} => "E"`           | anything    | unchanged    | a leading template is detached: the chain computes `sEEd` off the document    |
| `{a,ab}{c,bc} => "{{$2}}"`       | `abc`       | `bc`         | the hit binds `(a, bc)`, not `(ab, c)`: collision gave `abc` to value 1       |
| `{a,b}{$1} => "{{$1}}!"`         | `aa ab`     | `a! ab`      | the second factor re-spells the first: `aa` hits, `ab` never does             |
| `{ba} <=>[@spellings] "ab"`      | `bbaa`      | `aabb`       | three passes, each strictly earlier in `@spellings`; the fourth finds nothing |

## Sentinels

- `sentinel name` -- a declaration; the name stands wherever a universe stands, denoting one entry wearing one face: a noncharacter the host allocates (U+FDD0 up, in declaration order), the second seed after `C`. Admission is immediate -- the declaration resolves to a `uni` over a lone face, already a leaf of the six constructors -- so the floor never learns sentinels exist.
- Outside the alphabet -- the seeded `C` subtracts the noncharacters, so no `@C`-derived universe can touch a sentinel: the only thing that matches a sentinel is its name. Collision with document content is not avoided but unrepresentable, which is what makes the masking idiom sound.
- Engine-private -- sentinels never cross the document boundary. A document that arrives spelling a noncharacter is refused (Unicode reserves them against interchange), and a sentinel surviving into the final document is a script error -- a cleanup rule that did not fire -- never something to strip silently. The cleanup is in-language: `{@start,@end} => ""` is an ordinary statement, and the exit guard is what makes writing it a rule rather than a habit.
- `{{@name}}` -- the template read that splices a sentinel's face: the only way a sentinel enters text, since nothing else spells a noncharacter. It reads the environment where `$` and `$0` read the hit, which is what keeps it off the register inventory -- the four tokens stand.

## Diagnostics

- Errors live here and only here: unknown or cyclic name, malformed definition or arity, a register outside a definition body, an operand token no application binds, an exponent count that is not a decimal numeral, a capture read outside a template or in one no branch anchors, a factor read past the factors the query wrote, a pattern read at or right of the factor it reads or crossing a declaration, a pass that fails to shrink its declared measure or runs against a document the measure does not spell, a matcher run against an unguarded closure body, a sentinel read of a name that declares none, a noncharacter in the document at either boundary. The floor never rejects, so every rejection is an interpretation refusing a scope, never an expression failing to denote.
- Emptiness is not an error: a query denoting the empty universe matches nothing and says so. Meaningless stays legal; whether to warn is a later layer's taste, not this layer's law.

## Open

- `where` over a non-character radix -- value order and shortlex disagree there (`128` sits before `811` at values 20 and 3), so the spelling-range cut is wrong and the bounded digit-walk decomposition would cost digit-read registers. Scoped to character radixes until a use appears; the closure keeps the general value line denotable either way.
- Canonicalization -- carried as a binding rule so that `where`'s body stays writable; if a body ever needs to canonicalize something other than a bound parameter, it becomes a token and grows the inventory.
- Re-spelling by value -- the fold covers declared respellings, but a cross-radix cast (write the bound value under another universe: decimal to hex, a unary run's length as a decimal numeral) is value-indexing, which no expression computes. The candidate is a register generalizing `@0` -- the entry of a universe at the bound value, as `@0` is the entry at zero -- priced as ever; until it is admitted, respelling is what a fold declares.
- Filters and zero-width parts -- named statement chains (`:=` for the emit layer, inlined at use, acyclic as names are) and factors that go empty inside a nonempty whole (the whole-match ban stands). Conveniences, not power; each enters with an admission story when it is spelled.

## North star

The layer's witness is a bubble sort: sentinels mask each line, factor reads and back-references spell the adjacent out-of-order pair, and the contracting statement iterates the swap under a declared measure. It takes decimals of any magnitude at any padding and re-emits each at the width it arrived -- `where`'s canonical binding makes its cut a value cut whatever padding the read hit wearing, and `padfree` hangs every padding on one entry, so no width cap has to stand in for value order:

```text
sentinel start
sentinel end

uni c      = {@C, !{\n}}
uni line   = {@c, &@c}
uni d      = {0..9}
uni digits = {@d, &@d}
uni value  = {0..9}[numerals padfree]
uni list   = {@value, &{\,}{@value}}
uni sorted = {{@start}{@list}{@end}, &{\n}{@start}{@list}{@end}}

{@line} => "{{@start}}{{$}}{{@end}}"
{@start,\,}{@digits}{\,}{{0..9}[where 0..$2 padfree], !{{0..9}[where $2 padfree]}}{@end,\,} <=>[@sorted] "{{$1}}{{$4}},{{$2}}{{$5}}"
{@start,@end} => ""
```

The measure is `@sorted`: wrapped numeral lines with `@value` -- the value line of the decimal head, each entry wearing every padding -- as the component universe, so its entry order runs leftmost-numeral-slowest by *value*, whatever width a numeral arrived at. A swap puts the smaller value first, which moves the leftmost changed component strictly down that order, so every pass strictly precedes the last and the passes settle. The fourth factor's subtraction is what keeps the descent strict: the inclusive cut `where 0..$2` alone would also match a value-*equal* pair, whose swap re-dresses or repeats the document -- exactly what the measure refuses -- so subtracting the value-equal band makes an adjacent pair match exactly when it is out of order. That factor's entries wear infinitely many faces, which matching tolerates -- membership decides it -- and a canonical read would not; the sort's template reads every hit as it hit.
