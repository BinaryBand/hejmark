L1.5 is everything the host implements beyond denotation, and where a construct is admitted. **Admission rule:** a surface construct adds no denotation -- every application expands into the five constructors -- or it does not enter; what will not expand goes to L1 as an axiom, or nowhere. The floor never rejects, and this layer never guards: a malformed script has no expansion -- partiality, a fact about the text decided at expansion -- while every refusal of a program that does denote (bounded reads, decidable matching, termination, boundary hygiene) is L2's.

## Matching

| Rule | What it says |
| --- | --- |
| Query | a universe run against text, matching one entry by any face -- an empty query matches nothing (meaningless, not invalid) |
| Capture | the floor's `<value, face>` read off a hit -- it binds, never stores, the object already carrying the pair |
| Membership | matching is set membership -- does the text spell an entry? The matcher knows only spellings, no value or ordinal semantics |
| Longest-first | tile maximal-munch -- where one face is a proper prefix of another the longer wins; declaration order never selects |
| Zero-width | no match on the empty spelling (the unit's face) -- the unit is a factor, the product identity, not a query |

- **Back-references** -- the factor family stands in patterns: `{$k}` where a universe stands, or `$k` as a pipeline argument (`where 0..$2`), reads factor `k` of the same query, strictly to its left (only a bound factor reads). Admission is late-bound expansion: the matcher binds factors left to right, so the read is bound when its factor is tried, and substituting the face -- as it hit -- makes every attempt a plain floor query. Expansion parameterized by a binding, never new denotation. A face in a pattern position stands as its literal spelling; in an argument position it substitutes as a written argument, so numeral binding applies -- canonicalization makes `where 0..$2` a value cut whatever padding the read wore. A `$k` in a `uni`/`def` body stands in no query, so no expansion exists for it. Where a hit splits many ways, the collision rule decides (Emit, below), each split priced under its own bindings.
- **Scope** -- matching is decidable over guarded, non-negative closure bodies, and over every closure-free query. A body is **guarded** when each `&` stands adjacent to a factor no entry of which spells the empty face, so every unfolding consumes at least one character (`{@c,&@c}`, `{0,{1..9,&{0..9}}}`); it is **negative** when an `&` falls inside a subtraction operand. A subtraction with no `&` under it is closure-free and leaves the body settled. Unguarded and negative bodies denote -- the floor's totality -- but only semi-settle; the settlement theorem is L1's. This layer classifies only: the refusal to match outside the settled scope is L2's, never a denotation failure.

## Names

- **`uni name = {...}`** -- a declaration; the name stands wherever a universe stands (member, factor, subtraction operand), contributing entry-wise by the floor's splice rule -- which is how a name unions sub-universes without folding them, where a braced member quotients.
- **Reference** -- `@name` splices the declaration wherever a universe stands; the sigil keeps a name from ever reading as a spelling (`{cat}` the literal face, `{@cat}` the splice). One namespace, resolved at expansion; `@` is the one reserved name, and numerals are not declarable, which leaves the whole `@lo..hi` family -- `@0` included -- outside the namespace without reserving anything.
- **Acyclic** -- a name may not reach itself through its declaration, directly or through others. `&` is the language's only self-reference, and it lives on the floor; acyclicity keeps every expansion finite.
- **Literal faces** -- inside `{}` every character is the spelling it is, whitespace and parentheses included: `{cat dog}` is the one face `cat dog`, `{(a)}` the face `(a)`, and members divide on `,` alone (`{cat,dog}`, no space after the comma). Only the structural characters (`,` `{` `}` `[` `]` `!` `&` `@` `_` `^` `$` `"` `\`) are carved out; spell one literally with a `\` escape. Mnemonic escapes ride the same backslash: `\n`, `\t`, and `\r` spell the newline, tab, and carriage return, so a one-line declaration can carry whitespace, and `\..` is the literal two dots, since only the *sequence* `..` is the range -- a lone `.` is already a literal dot, so `\.` is not an escape. Every other escaped character has no reading, which is what keeps the rest of the alphabet open. No insignificant whitespace exists to lay a universe out with -- a space or newline between braces is content, not formatting.

## Definitions

- **Form** -- `def name params = body`, applied only through the modifier pipeline `A[f x g y]`: stages left to right, each threading its result to the next as `_`, arguments following the stage name (`[shorter w]`). A zero-parameter name splices bare (`@name`); a parameterized one applies to the operand on its left. The width toolkit cuts `@str` by width (`@str[shorter w]`), exact because `@str` is suffix-closed -- which is how `pad` gets its absolute band.
- **Substitution** -- application replaces the body's parameters with the stage's arguments and `_` with the stage operand, expanding until only constructors remain. Juxtaposition is always a product (`@a@b` never applies `a` to `b`; a space between a name and a word is a literal face), so application is exactly the pipeline. Definitions are non-recursive (recursion is the closure's) and acyclic, so expansion terminates.
- **Head and chaining** -- every stage in one bracket reads the same **head**, its left operand (not the threaded `_`), so one radix rides the fused bracket; a new bracket rebinds the head to the whole prior expression, and a bare-spliced name shares the caller's head.

| Expression | Head for each stage | `pad` fills with |
| --- | --- | --- |
| `{0..9}[where 8..12 pad 2]` | `@` pinned to `{0..9}`, both stages | `0` -- `08`, `09` (the base digit) |
| `{0..9}[where 8..12][pad 2]` | rebinds; the head for `pad` is `{0..9}[where 8..12]` | `8` -- `88`, `89` (`pad` reaches the cut radix's own `@0`) |

A stage reading neither the head nor a def that does -- the width toolkit reads only `_` and the constant `@char` -- gives the same result either way.

- **Numeral parameters** -- two kinds, split by what the numeral is for:

| Kind | Used by | Binds as | Reads a value line? |
| --- | --- | --- | --- |
| value | `where`/`below` bounds | canonicalized in the head radix (`aa` = `a`, value 0) | yes -- names a position on it |
| count | a width, an exponent count | a decimal numeral whatever the head (`pad 2` over `{8,9,10,11,12}`) | no -- feeds expander arithmetic |

A lone numeral binds a pair parameter as the degenerate `n..n` -- union's singleton case, already the floor's theorem (`{2..2}` = `{2}` under range compression) -- so `pad 2` is `pad 2..2`, the degenerate pair reading the same for both kinds.

- **Exponent** -- `A^x..y` is `A` written adjacent a span of times: the union of `A^x` through `A^y`, each an iterated product down to `A^0` = the unit (the floor's product-identity theorem). A lone `A^n` is the degenerate `A^n..n`. Each count is a decimal numeral -- or a parameter that bound one, as `pad`'s `^{w'}` -- never a value read: expansion counts, never denotes, and a non-numeral count leaves no expansion. Both counts are attained, the band a *closed* span (`y` below `x` an empty union), so the notation never spells unbounded repetition -- an open `A^x..` has no reading, that being closure's (`&`), not the exponent's. Counting is the expander's arithmetic, not the floor's compression list; every application expands into iterated product and finite union.

## Registers

- The in-language spellings of the expander's metafunctions -- the reads a written body needs that no expression computes. The inventory at a glance, each row detailed below:

| Spelling | Side | Reads |
| --- | --- | --- |
| `@` | expander | the pipeline head as a universe, unread -- every other `@` read is a read of it; anchors the value line to the head's radix, and reads empty (total) on an empty head |
| `@0` | expander | the zero entry, the value axis's zero -- the degenerate cut `@0..0` |
| `@lo..hi` | expander | the value family: the head's value line cut to values `lo` through `hi`, both attained |
| `$` | emitter | the hit as it hit -- the bound entry at its bound face |
| `$0` | emitter | the hit's canonical face, the face axis's zero |
| `$1..$n` | emitter | the factor family: factor `k` of the query as it hit, 1-based -- stands in a pattern as `{$k}` |

Not registers -- spellings a body resolves at expansion that compute no metafunction read:

| Spelling | What it is | Bound / resolved |
| --- | --- | --- |
| `_` | the stage operand -- the threaded pipeline value | by substitution at each pipeline application; a scope error reached any other way |
| *a def's parameters* (`w`, `lo..hi`, ...) | the def's named arguments | by substitution at application, replaced with the stage's arguments -- the same step that fills `_` |
| `@name` | a name splice -- a `uni`/`def`/`sentinel` reference | at expansion, by looking up the declaration; the sigil tells a splice from a face |
| `{{@name}}` | the template splice of a sentinel's face | in the emit environment, where `$`/`$0` read the hit -- not a metafunction read |

The shortlex range interval a range lists, numeral canonicalization, and the degenerate pair `n..n` are binding rules with no token at all -- in neither table.

- **`@lo..hi`, its own read** -- no expression selects an entry by value, so the value cut is never derivable from `@`'s spellings. Both bounds are always written: the line has a least entry (`@0`) but no greatest, so no open `@lo..` closes -- a universe needing every value is the generating closure written outright (`{0,{1..9,&{0..9}}}`, L1; or `{@d,&@d}` where only membership matters). Entries come at their canonical faces, the family cutting the value axis and leaving the face to later stages.
- **Digit-walk** -- the family's radix-general expansion: the head's entries in value order are the radix's digits, so a bound decomposes by digit position into iterated product and union (the five constructors, reached by counting positions -- expander arithmetic, not denotation). No premise about spellings enters, the whole difference from a spelling range, which needs value order and shortlex to agree and fails over digits wearing wider faces.
- **Bounds** -- each binds canonicalized in the head's own radix (a capture read substitutes the face it hit, then binds the same), naming positions on the line the head generates in the head's own numerals. A hit never cuts another radix's line -- that would be a cast, which nothing computes (Worked derivations, below).
- **Totality** -- `hi` below `lo`, or an empty head, reads empty (`@0` included); a fill on that `@0` still no-ops, a fold over an empty operand being the unit -- the floor's totality.
- **The inventory, closed** -- two tokens (`@`, `$`), two addressed families (`@lo..hi`, which carries `@0`; and `$1..$n`), one face-zero read (`$0`): the six rows above. The face read sits on the `$` side alone because only a hit ever holds a non-canonical face -- `@`'s family already reads canonical faces, so a face-zero read of `@` would say nothing new.

## Worked derivations

Transformation runs on three axes -- alphabet, value, face -- and none needs a primitive: each dissolves into the floor.

- **Alphabet axis** -- keeping and dropping entries are both subtraction: a difference drops the named entries, an intersection keeps them by subtracting the rest.
- **Value axis** -- the closure generates the value line; cutting a bounded stretch of it is the one read no expression computes, so the cut is the register family and `where` its pipeline spelling. The whole line is the canonical-numeral closure -- `{0,{1..9,&{0..9}}}` (L1), first-appearance order being value order: the zero first, then the closure's stages width by width, product order within a width being value order -- so a universe needing every value is written from that generator outright, and `where` only ever cuts a bounded `lo..hi` out of it. A tail from `k` is that canonical closure less a bounded prefix. The digit-walk cuts by position, exact over any radix and order-preserving; a spelling range is exact only where value order and shortlex agree. `where` never reads the pipe: it regenerates the value line from the head and cuts it, a generator anchored to the radix rather than a filter of its operand, so its body carries no `_` and means the same at any stage.
- **Face axis, by value** -- a fold carries a *declared* respelling: an input spelling rides as a later face and the output as face 0, transformation without arithmetic. What it does not carry is a *cast* -- a bound value written under a second universe (decimal to hex, a unary run's length as a decimal). That is value-indexing across two radixes: the value family cuts one head's value line and names its bounds in that head's numerals, so it never crosses. A cast would need the value read as a value rather than a spelling, which no expression computes and no register spells.
- **Face axis** -- subtraction cuts it directly, stripping the face that claims each spelling; an entry drops only with its last face. A width cut is one subtraction of the unwanted widths.

The std that the finish line asks for is written over this surface; its entries are declared in L3 (`docs/foundation/L3.md`). `char`, the one `uni` the spec seeds, is the floor's code-point set `C` less the noncharacters (the sentinel space, below); the derivations below work over `str` (every spelling), the width toolkit (`shorter`/`upto`/`longer`), `where` and its top-exclusive sibling `below`, `pad`, and `padfree`.

`pad` is two face cuts: `fill` is one entry wearing both the empty spelling and the pad character as faces (L3), so `fill^{w'}` gives each entry its faces from bare up to `w'` fills, and the subtractions strip every face too narrow or too wide -- no arithmetic on `w'`, since the overshoot faces fall to `longer w'` regardless. `padfree` is the uncapped `pad`: dropping the cap dissolves the exponent into a fold (`zfold`, one entry wearing every finite run of fills as a face), so `{@zfold _}` moves nothing on the value axis and hangs every zero-padding on the face axis. Matching a `padfree` result stays in scope (membership decides it); a canonical read does not, since every entry wears infinitely many faces -- the read the bounded `pad` keeps.

| Expression | Denotes | Why |
| --- | --- | --- |
| `{0..9}[where 8..12]` | 8, 9, 10, 11, 12 | the value line cut to `8..12`: width-1 digits from 8, width-2 canonicals to 12 |
| `{a..z}[where aa..cc]` | a, ..., z, ba, ..., cc (55 entries) | `aa` binds canonical as `a`, so the width-1 numerals enter the range |
| `{8,9,10,11,12}[pad 2]` | 88, 89, 10, 11, 12 | `@0` is `8`; `shorter 2` strips the bare `8`, `9`; `longer 2` strips `810`, `888`, ... |
| `{0..9}[where 8..12 pad 1..2]` | {8,08}, {9,09}, 10, 11, 12 | head fills `0`; widths 1-2 both legal, so `8` keeps both faces; `010` is stripped |
| `{a,bb}[where a..bbbb]` | a, bb, bba, bbbb | values 0-3; a spelling range would also admit `bbaa` -- value 4, yet shortlex-below `bbbb` |
| `{a,bb}[where bb..bba]` | bb, bba | a non-character radix: the digit-walk cuts positions, so values 1-2 come out in order |

## Emit

Emit is the write half of using a universe against text: interpretation, not expression -- no template builds a universe the constructors do not reach, and every read it needs is priced as a register. Two objects and one join rule carry the section.

- **Text objects and branches** -- a **text object** is where spellings live: the document a statement runs against, or a string a template constructs. A **branch** is a span of one text object carrying the capture its match bound; the span (`[start, end]`) and the floor's `<value, face>` are one datum seen twice, the object's text over the span being exactly the bound face. Only branches cross `=>` -- never a detached value, always a pointer into text.
- **Steps** -- a statement is steps joined by `=>`, each a **query** (a universe expression, pipelines included) or a **template** (`"..."`: literal text plus `{{...}}` interpolation sites, each holding one capture read). Arrows are top-level only: inside a brace or quote, `=>` is literal text.
- **Lines** -- one declaration or statement per logical line. A brace or quote spanning physical lines stays one statement; a line whose first token is `=>` continues the one above; blank lines separate nothing; `//` comments run to end of line at brace depth 0 only, so `{http://x}` stays a face.
- **Query step** -- refines: tiles the branch's text by the matcher above (inheriting its scope), one sub-branch per match, and a query that matches nothing stops the branch (the guard reading). Tiled matches are disjoint, so commits never contend.
- **Template step** -- constructs: builds a string, literal text landing as written and each interpolation rendering its read. An incoming branch anchors it -- the string commits over the branch's span, never rolled back, and each site continues as a sub-branch at its rendered span carrying its binding, so decoration lands but never flows. No site: it commits and ends the branch. No incoming branch (a leading template): the string is detached, the rest of the chain computes over it, and the document never changes.
- **Bootstrap** -- a leading query branches into the statement's target; a leading template is the detached string above. The whole-document rewrite is an idiom, not a case: `{@str} => "..."` tiles the entire text as one entry of `str`, maximal munch taking the longest face -- and does not fire on an empty document, since the one face on offer is the empty spelling and zero-width never matches.
- **Capture reads** -- the emitter's registers `$` and `$0` (register table above). `$0` is the zero of the face axis as `@0` is of the value axis, and the fold carries the transformation: an input spelling rides as a later face, the output as face 0.
- **Factor reads** -- adjacency is the product, so the hit binds a tuple and `$k` (register table above) is component `k` as it hit over its sub-span. Where a spelling splits many ways the floor's collision rule has already decided -- the split belongs to its least `<value, face>` claimant -- so `{a,ab}{c,bc}` against `abc` reads `$1` as `a`, `$2` as `bc`. Factors are the written units, an exponent's repetitions staying inside theirs (`{a}^3{b}` offers `$1` for all three, `$2` for the `b`). Every read is as-it-hit, so a factor's entries wearing infinitely many faces cost nothing -- matchable, not canonically readable. What is priced is the split: a uniquely-pinned one reads free, an ambiguous one streams candidate tuples in value order, refused past budget rather than guessed (L2).
- **Contraction** -- `query <=> template` is the one iterated statement: the ordinary pass (tile, commit, splice) re-run until it leaves the document unchanged -- a fixpoint. It carries no declared measure: it settles when the rewrite stops moving the document, and nothing on the arrow proves in advance that it will. Bounding a run that never reaches a fixpoint is L2's.
- **Splice** -- a statement's result is its committed strings laid over their spans with the text between kept, at every depth; the flat list with the spans dropped is the extraction view of the same result.

| Statement | Against | Yields | Why |
| --- | --- | --- | --- |
| `{{cat,feline}} => "{{$0}}"` | `my feline` | `my cat` | `feline` binds face 1; `$0` writes face 0 |
| `{a,e,i,o,u} => ""` | `pattern` | `pttrn` | the empty string commits over each match |
| `{@str} => "<b>{{$}}</b>"` | `abc` | `<b>abc</b>` | one branch spans the whole text; decoration lands, `$` re-emits the hit |
| `{a} => {b}` | `banana` | `banana` | a mid-chain query is a guard: no `b` inside an `a`-match, every branch stops |
| `"seed" => {e} => "E"` | anything | unchanged | a leading template is detached: the chain computes `sEEd` off the document |
| `{a,ab}{c,bc} => "{{$2}}"` | `abc` | `bc` | the hit binds `(a, bc)`, not `(ab, c)`: collision gave `abc` to value 1 |
| `{a,b}{$1} => "{{$1}}!"` | `aa ab` | `a! ab` | the second factor re-spells the first: `aa` hits, `ab` never does |
| `{ba} <=> "ab"` | `bbaa` | `aabb` | three passes rewrite; the fourth leaves the document unchanged and stops |

## Sentinels

- **`sentinel name`** -- a declaration; the name stands wherever a universe stands, denoting one entry over one face: a fresh noncharacter, outside `char` and apart from every other sentinel -- the second seed after `char`. That is all the denotation reads; which noncharacter a name draws is the host's allocation scheme, boundary hygiene beside the ingest guard and the exit strip (L2), as is the refusal when declarations outrun the finite pool. Admission is immediate -- a `uni` over a lone face, already a leaf of the five constructors -- so the floor never learns sentinels exist.
- **Outside the alphabet** -- `char` subtracts the noncharacters, so no `@char`-derived universe can touch a sentinel: the only thing that matches one is its name. Collision with document content is not avoided but unrepresentable.
- **Engine-private** -- sentinels never cross the document boundary. A sentinel is a real noncharacter while the script runs, so statements can match it; at exit every declared sentinel is stripped, so nothing engine-private ships and no cleanup statement has to be written. The way *in* is guarded: a document that arrives spelling a noncharacter is refused (L2). Since `char` excludes the noncharacters and ingest refuses any that slip in, the exit strip removes exactly the masks the script wrote.
- **`{{@name}}`** -- the template read that splices a sentinel's face, the only way a sentinel enters text. It resolves in the emit environment, where `$` and `$0` read the hit, and computes no metafunction read -- so it is not a register.

## Diagnostics

- Where no expansion exists the script has no reading -- partiality of the expansion, decided at expansion time, never a guard: unknown or cyclic name, malformed definition or arity, an expander register (`@`, `@0`, `@lo..hi`) where no pipeline head binds it, an operand token no application binds, an exponent count that is not a decimal numeral, a value bound the head radix does not spell, an escape naming neither a structural character nor a spelled sequence, a capture read outside a template or in one no branch anchors, a factor read past the factors the query wrote, a pattern read at or right of the factor it reads or crossing a declaration, a sentinel read of an undeclared name. Every refusal -- declining a program that does denote: a read past budget, a matcher on an unguarded body, a `<=>` that never settles, a noncharacter at the boundary, a sentinel pool outrun -- is L2's. The floor denotes, this layer expands or is undefined, and L2 alone refuses.
- Emptiness is not an error: a query denoting the empty universe matches nothing and says so. Meaningless stays legal; whether to warn is a later layer's taste.

## North star

The layer's witness is a bubble sort: sentinels mask each line, factor reads and back-references spell the adjacent out-of-order pair, and `<=>` iterates the swap to a fixpoint, the sentinels clearing at exit. It takes decimals of any magnitude at any padding and re-emits each at the width it arrived -- `where`'s canonical binding makes the cut a value cut whatever padding the read hit wearing, and `padfree` hangs every padding on one entry, so no width cap stands in for value order:

```text
sentinel start
sentinel end

uni c      = {@char,!{\n}}
uni line   = {@c,&@c}
uni d      = {0..9}
uni digits = {@d,&@d}

{@line} => "{{@start}}{{$}}{{@end}}"
{@start,\,}{@digits}{\,}{0..9}[below 0..$2 padfree]{@end,\,} <=> "{{$1}}{{$4}},{{$2}}{{$5}}"
```

`c` is closure-free, so `line` is guarded and non-negative and the whole query sits in the settled scope. The contraction carries no measure: it iterates until a pass leaves the document unchanged. `below` is the value cut less its top endpoint (`{@lo..hi,!{@hi..hi}}`, L3), so factor 4 matches exactly when the adjacent pair is out of order and a value-equal pair never matches -- each pass strictly reduces the inversions in the line, and the run settles at the sorted one. Its entries wear infinitely many faces (matchable, not canonically readable), so the template reads every hit as it hit.

The program, witnessed -- one document in, its lines each sorted, the program itself fixed:

| Against | Yields | Why |
| --- | --- | --- |
| `3,1,2` | `1,2,3` | each pass swaps an adjacent inversion; iteration settles at the ascending line |
| `10,9` | `9,10` | value order, not shortlex: `9` precedes `10` though `"10"` precedes `"9"` as text |
| `09,3` | `3,09` | `where`'s value cut ignores the pad; each numeral re-emits at its arrival width |
| `007,7` | `007,7` | equal value: factor 4 strips the value-equal band, so the pair never matches to swap |
| `2,1\n4,3` | `1,2\n3,4` | the start/end sentinels mask each line, so the sort descends each line on its own |

## Finish line

> L1.5 is done when the std of the layer above -- `uni hex = {0..9,a..f}`, `where`, `pad`: nothing but declarations -- is written over this surface exactly as the derivations above spell it, with the register inventory no larger than it is on this page.
