L1.5 is everything the host implements beyond denotation, and where a construct is admitted. **Admission rule:** a surface construct adds no denotation -- every application expands into the five constructors -- or it does not enter; what will not expand goes to L1 as an axiom, or nowhere. The floor never rejects, so rejection is interpretation's: well-formedness here, the finite-execution refusals (bounded reads, decidable matching, termination, boundary hygiene) in L2.

## Matching

- **Query** -- a universe run against text, matching one entry by any face. An empty-universe query matches nothing; emptiness is meaningless, not invalid.
- **Capture** -- the floor's `<value, face>` read off a hit. The object already carries the pair, so a capture binds, never stores.
- **Membership** -- matching is set membership: does the text spell an entry? The matcher knows only spellings, no value or ordinal semantics.
- **Longest-first** -- tile the text maximal-munch: where one face is a proper prefix of another, the longer wins. Declaration order never selects a match.
- **Zero-width** -- no match is ever accepted on the empty spelling (the unit's face). The unit is a factor, the product identity, not a query.
- **Back-references** -- the factor family stands in patterns: `{$k}` where a universe stands, or `$k` as a pipeline argument (`where 0..$2`), reads factor `k` of the same query, strictly to its left (only a bound factor reads). Admission is late-bound expansion: the matcher binds factors left to right, so the read is bound when its factor is tried, and substituting the face -- as it hit -- makes every attempt a plain floor query. Expansion parameterized by a binding, never new denotation. A face in a pattern position stands as its literal spelling; in an argument position it substitutes as a written argument, so numeral binding applies -- canonicalization makes `where 0..$2` a value cut whatever padding the read wore. A `$k` in a `uni`/`def` body stands in no query and is refused. Where a hit splits many ways, the collision rule decides (Emit, below), each split priced under its own bindings.
- **Scope** -- matching is decidable only where the settlement theorem reaches: all-guarded closure bodies (closure-free queries always). An unguarded or negative body denotes -- the floor's totality -- but only semi-settles, so matching it is out of scope: refused by L2, never a denotation failure.

## Names

- **`uni name = {...}`** -- a declaration; the name stands wherever a universe stands (member, factor, subtraction operand), contributing entry-wise by the floor's splice rule -- which is how a name unions sub-universes without folding them, where a braced member quotients.
- **Reference** -- `@name` splices the declaration wherever a universe stands. The sigil keeps a name from ever reading as a spelling: `{cat}` is the literal face, `{@cat}` the splice. One namespace, resolved at expansion; its two reserved names are the registers -- bare `@` the head, `@0` its zero entry -- and numerals are not declarable, which keeps `@0` free.
- **Acyclic** -- a name may not reach itself through its declaration, directly or through others. `&` is the language's only self-reference, and it lives on the floor; acyclicity keeps every expansion finite.
- **Literal faces** -- inside `{}` every character is the spelling it is, whitespace and parentheses included: `{cat dog}` is the one face `cat dog`, `{(a)}` the face `(a)`, and members divide on `,` alone (`{cat,dog}`, no space after the comma). Only the structural characters (`,` `{` `}` `[` `]` `!` `&` `@` `_` `^` `$` `"` `\`) are carved out; spell one literally with a `\` escape (a lone `.` is already a literal dot -- only `..` is the range). No insignificant whitespace exists to lay a universe out with -- a space or newline between braces is content, not formatting.

## Definitions

- **Form** -- `def name params = body`, applied only through the modifier pipeline `A[f x g y]`: stages left to right, each stage's result the next stage's operand `_`, a stage's arguments following its name (`[shorter w]`). A zero-parameter name splices bare (`@name`) wherever a universe stands; a parameterized one applies to the operand on its left. The std's width toolkit cuts that operand by width (`{X}[shorter w]`), so `pad` applies it to `@str` for the absolute band.
- **Substitution** -- application replaces the body's parameters with the stage's arguments and `_` with the stage operand, yielding an expression over names, registers, and the floor; expansion continues until only constructors remain. `_` binds only at a pipeline application, so a `_` reached any other way is a scope error. Juxtaposition is always a product -- `@a@b` never applies `a` to `b`, and a space between a name and a word is a literal face -- so application is exactly the pipeline. Definitions are non-recursive (recursion is the closure's) and acyclic like names, so expansion terminates.
- **Head** -- within one bracket every stage reads the same **head** -- the bracket's left operand, not the threaded stage operand -- so one radix rides the fused bracket: `{0..9}[where 8..12 pad 1..2]` fills with `0` because the head is `{0..9}`, whatever `where` left in the pipe. A bare-spliced name shares the caller's head.
- **Chaining** -- one rule covers both: a bracket binds the head to its left operand, and every stage in that bracket shares it; a new bracket rebinds. So `A[f g]` pins `@` to `A` for both stages, while `A[f][g]` = `(A[f])[g]` rebinds `@` to `A[f]` for `g` -- postfix application closed over universes, `g` reading `A[f]` as its head exactly as if it were written out. The rebind is observable wherever a stage reads the head: `{0..9}[where 8..12 pad 1..2]` fills with the base digit `0` (`08`, `09`), but `{0..9}[where 8..12][pad 1..2]` fills with the cut radix's own zero `8` (`88`, `89`), since `pad` reaches the head through `fill`'s `@0`. A stage reading neither the head nor a def that does -- the width toolkit reads only `_` and the constant `@char` -- gives the same result either way.
- **Numeral parameters** -- a parameter written as a numeral or numeral pair (`lo..hi`) binds canonicalized in the head radix: leading zero digits strip, so `aa` binds as `a` (value 0 either way). A lone numeral binds a pair parameter as the degenerate pair `n..n` -- the surface's echo of union's singleton case, already the floor's theorem since `{2..2}` is `{2}` under range compression -- so `pad 2` binds `w..w'` at `2..2`.
- **Exponent** -- `A^n` is `A` written adjacent `n` times: iterated product down to `A^0` = the unit, by the floor's product-identity theorem. The count is a decimal numeral -- or a parameter that bound one, as `pad`'s `^{w'}` -- never a value read in any universe: expansion counts, it never denotes, and a count that does not spell a decimal numeral is refused. Counting is the expander's arithmetic and refusal this layer's privilege, which seats the notation here rather than on the floor's compression list; every application expands into iterated product, so the admission rule holds.

## Registers

- The in-language spellings of the expander's metafunctions -- the reads a written body needs that no expression computes. The precedent is the floor's own bounded range: `{a..z}` = `{a..,!{s..}}` computes the successor `s` at expansion time, and a register is the same move given a token, so declarations, not just prose, can lean on it.
- **`@`** -- the pipeline head itself, as a universe: the head unread, and every other register a read of it. It anchors the value line to the radix wherever a definition sits in the pipe. On an empty head it reads as the empty universe -- total.
- **`@lo..hi`** -- the head's value line, cut to the entries at values `lo` through `hi`. Not derivable from `@`: no expression selects an entry by value, so a value cut is its own read, never a cut of the head's spellings. `@0` is the degenerate `@0..0` (the zero entry, keeping its own spelling as a lone numeral keeps `n..n`); `@lo..`, with `hi` absent, is the open case -- every entry from `lo` on, so `@0..` is the whole line and the family generates as well as cuts. Entries read at their canonical faces: the family cuts the value axis and leaves the face axis to the stages that follow it.
- **Digit-walk** -- the family's expansion, and why it is radix-general. The head's entries in value order are the radix's digits, so a bound decomposes into digit positions: numerals narrower than the bound, then one term per position carrying that position's prefix, a cut of the digits below its digit, and free digits to the right. Iterated product and union -- the five constructors, reached by counting positions, which is the expander's arithmetic and not a denotation. No premise about spellings enters, which is the whole difference from a spelling range: that needs value order and shortlex to agree, and over a radix whose digits wear wider faces they do not.
- **Bounds** -- a written bound binds canonicalized in the head radix, as every numeral parameter does; a bound written as a capture read substitutes the face it hit and then binds the same way. Both bounds read *in the head's own radix* -- the family cuts the value line the head generates and names positions on it in the head's own numerals. A hit read under one radix does not cut another radix's value line -- that would be a cast, which nothing here computes (Worked derivations, below).
- **Totality:** `hi` below `lo` reads as the empty universe, a bound past the head's order type saturates, and an empty head has no entries to cut -- so `@0` reads as the unit there and a fill built on it no-ops. An absent `hi` has no bound to outrun: the line's tail up to its order type, never past it.
- **The inventory, closed:** the shortlex successor (no token), numeral-parameter canonicalization and the degenerate pair (binding rules, no token), `@` and the value family `@lo..hi` for the expander, and `$` and `$0` for the emitter with the factor family `$1..$n` addressing the hit's written factors (read in a template, or standing in a pattern). Four tokens and two addressed families -- each family an addressing of a token already on the shelf (`$1..$n` addresses `$` by factor, `@lo..hi` addresses `@` by value), not a new one. A new register faces the scrutiny a new axiom does, and the finish line is measured by the inventory staying this size.

## Worked derivations

Transformation runs on three axes -- alphabet, value, face -- and none needs a primitive: each dissolves into the floor.

- **Alphabet axis** -- keeping and dropping entries are both subtraction: a difference drops the named entries, an intersection keeps them by subtracting the rest.
- **Value axis** -- the closure generates the value line; cutting it is the one read no expression computes, so the cut is the register family and `where` its pipeline spelling. Its open case is the whole line: `where 0..` (`{@0..}`) is the value line itself -- the zero digit first, then the closure's stages width by width, product order within a width being value order -- so generating the line and cutting a stretch of it are one mechanism. The digit-walk cuts by position, exact over any radix and order-preserving; a spelling range is exact only where value order and shortlex agree. `where` never reads the pipe: it regenerates the value line from the head and cuts it, a generator anchored to the radix rather than a filter of its operand, so its body carries no `_` and means the same at any stage.
- **Face axis, by value** -- a fold carries a *declared* respelling: an input spelling rides as a later face and the output as face 0, transformation without arithmetic. What it does not carry is a *cast* -- a bound value written under a second universe (decimal to hex, a unary run's length as a decimal). That is value-indexing across two radixes: the value family cuts one head's value line and names its bounds in that head's numerals, so it never crosses. A cast would need the value read as a value rather than a spelling, which no expression computes and no register spells.
- **Face axis** -- subtraction cuts it directly, stripping the face that claims each spelling; an entry drops only with its last face. A width cut is one subtraction of the unwanted widths.

The std that the finish line asks for is written over this surface; its entries are declared in L3 (`docs/foundation/L3.md`). `char`, the one `uni` the spec seeds, is the floor's code-point set `C` less the noncharacters (the sentinel space, below); the derivations below work over `str` (every spelling), the width toolkit (`shorter`/`upto`/`longer`), `where` and its top-exclusive sibling `below`, `pad`, and `padfree`.

`pad` is two face cuts: `fill^{w'}` gives each entry its faces from bare up to `w'` extra fills, and the subtractions strip every face too narrow or too wide -- no arithmetic on `w'`, since the overshoot faces fall to `longer w'` regardless. `padfree` is the uncapped `pad`: dropping the cap dissolves the exponent into a fold (`zfold`, one entry of order type $1$), so `{@zfold _}` moves nothing on the value axis and hangs every zero-padding on the face axis. Matching a `padfree` result stays in scope (membership decides it); a canonical read does not, since every entry wears infinitely many faces -- the read the bounded `pad` keeps.

| Expression | Denotes | Why |
| --- | --- | --- |
| `{0..9}[where 8..12]` | 8, 9, 10, 11, 12 | the value line cut to `8..12`: width-1 digits from 8, width-2 canonicals to 12 |
| `{a..z}[where aa..cc]` | a, ..., z, ba, ..., cc (55 entries) | `aa` binds canonical as `a`, so the width-1 numerals enter the range |
| `{8,9,10,11,12}[pad 2]` | 88, 89, 10, 11, 12 | `@0` is `8`; `shorter 2` strips the bare `8`, `9`; `longer 2` strips `810`, `888`, ... |
| `{0..9}[where 8..12 pad 1..2]` | {8,08}, {9,09}, 10, 11, 12 | head fills `0`; widths 1-2 both legal, so `8` keeps both faces; `010` is stripped |
| `{a,bb}[where a..bbbb]` | a, bb, bba, bbbb | a non-character radix: the digit-walk cuts positions, so values 0-3 come out in order |
| `{a,bb}[where bb..bba]` | bb, bba | values 1-2; a spelling range would cut shortlex here and miss `bba` for `bbb` |

## Emit

Emit is the write half of using a universe against text: interpretation, not expression -- no template builds a universe the constructors do not reach, and every read it needs is priced as a register. Two objects and one join rule carry the section.

- **Text objects and branches** -- a **text object** is where spellings live: the document a statement runs against, or a string a template constructs. A **branch** is a span of one text object carrying the capture its match bound; the span (`[start, end]`) and the floor's `<value, face>` are one datum seen twice, the object's text over the span being exactly the bound face. Only branches cross `=>` -- never a detached value, always a pointer into text.
- **Steps** -- a statement is steps joined by `=>`, each a **query** (a universe expression, pipelines included) or a **template** (`"..."`: literal text plus `{{...}}` interpolation sites, each holding one capture read). Arrows are top-level only: inside a brace or quote, `=>` is literal text.
- **Lines** -- one declaration or statement per logical line. A brace or quote spanning physical lines stays one statement; a line whose first token is `=>` continues the one above; blank lines separate nothing; `//` comments run to end of line at brace depth 0 only, so `{http://x}` stays a face.
- **Query step** -- refines: tiles the branch's text by the matcher above (inheriting its scope), one sub-branch per match, and a query that matches nothing stops the branch (the guard reading). Tiled matches are disjoint, so commits never contend.
- **Template step** -- constructs: builds a string, literal text landing as written and each interpolation rendering its read. An incoming branch anchors it -- the string commits over the branch's span, never rolled back, and each site continues as a sub-branch at its rendered span carrying its binding, so decoration lands but never flows. No site: it commits and ends the branch. No incoming branch (a leading template): the string is detached, the rest of the chain computes over it, and the document never changes.
- **Bootstrap** -- a leading query branches into the statement's target; a leading template is the detached string above. The whole-document rewrite is an idiom, not a case: `{@str} => "..."` tiles the entire text as one entry of `str`, maximal munch taking the longest face -- and does not fire on an empty document, since the one face on offer is the empty spelling and zero-width never matches.
- **Capture reads** -- the emitter's registers. `$` is the hit as it hit, the bound entry at its bound face; `$0` is its canonical face -- the zero of the face axis, as `@0` is the zero of the value axis. The fold carries the transformation: an input spelling rides as a later face, the output as face 0.
- **Factor reads** -- `$1..$n`, one per top-level factor, 1-based since `$0` is the canonical read. Adjacency is the product, so the hit binds a tuple and `$k` is component `k`, spelled as it hit over its sub-span. Where the spelling splits more than one way, the floor's collision rule has already decided -- the spelling belongs to its least `<value, face>` claimant -- so `{a,ab}{c,bc}` against `abc` reads `$1` as `a` and `$2` as `bc`, the `(ab, c)` split having lost at the floor. Factors are the written units: an exponent's repetitions stay inside theirs, so `{a}^3{b}` offers `$1` (all three) and `$2`. Reads are as-it-hit only -- a factor's entries may wear infinitely many faces, matchable but not canonically readable, so there is no per-factor canonical read. The price is `$0`'s: a uniquely-pinned split reads for free, an ambiguous one streams entries in value order, refused past the host's budget rather than guessed (L2).
- **Contraction** -- `query <=> template` is the one iterated statement: the ordinary pass (tile, commit, splice) re-run until it leaves the document unchanged -- a fixpoint, iterated in value order. It carries no declared measure: it settles when the rewrite stops moving the document, and nothing on the arrow proves in advance that it will. Bounding a run that never reaches a fixpoint is L2's.
- **Splice** -- a statement's result is its committed strings laid over their spans with the text between kept, at every depth; the flat list with the spans dropped is the extraction view of the same result.

| Statement | Against | Yields | Why |
| --- | --- | --- | --- |
| `{{cat,feline}} => "{{$0}}"` | `my feline` | `my cat` | `feline` binds face 1; `$0` writes face 0 |
| `{a,e,i,o,u} => ""` | `pattern` | `pttrn` | the empty string commits over each match |
| `{@str} => "<b>{{$}}</b>"` | `abc` | `<b>abc</b>` | one branch spans the whole text; decoration lands, `$` re-emits the hit |
| `{a} => {b}` | `banana` | `banana` | a mid-chain query is a guard: no `b` inside an `a`-match, every branch stops |
| `"seed" => {e} => "E"` | anything | unchanged | a leading template is detached: the chain computes `sEEd` off the document |
| `{a,ab}{c,bc} => "{{$2}}"` | `abc` | `bc` | the hit binds `(a, bc)`, not `(ab, c)`: collision gave `abc` to value 1 |
| `{a,b}{$1} => "{{$1}}!"` | `aa ab` | `a! ab` | the second factor re-spells the first: `aa` hits, `ab` never does |
| `{ba} <=> "ab"` | `bbaa` | `aabb` | three passes rewrite; the fourth leaves the document unchanged and stops |

## Sentinels

- **`sentinel name`** -- a declaration; the name stands wherever a universe stands, denoting one entry over one face: a noncharacter the host allocates (U+FDD0 up, in declaration order), the second seed after `char`. Admission is immediate -- a `uni` over a lone face, already a leaf of the five constructors -- so the floor never learns sentinels exist.
- **Outside the alphabet** -- `char` subtracts the noncharacters, so no `@char`-derived universe can touch a sentinel: the only thing that matches one is its name. Collision with document content is not avoided but unrepresentable, which is what makes the masking idiom sound.
- **Engine-private** -- sentinels never cross the document boundary. A sentinel is a real noncharacter while the script runs, so statements can match it; at exit every declared sentinel is stripped, so nothing engine-private ships and no cleanup statement has to be written. The way *in* is guarded: a document that arrives spelling a noncharacter is refused (L2). Since `char` excludes the noncharacters and ingest refuses any that slip in, the exit strip removes exactly the masks the script wrote.
- **`{{@name}}`** -- the template read that splices a sentinel's face, the only way a sentinel enters text. It reads the environment where `$` and `$0` read the hit, which keeps it off the register inventory -- the four tokens stand.

## Diagnostics

- Errors of well-formedness live here: unknown or cyclic name, malformed definition or arity, a register outside a definition body, an operand token no application binds, an exponent count that is not a decimal numeral, a value bound the head radix does not spell, a capture read outside a template or in one no branch anchors, a factor read past the factors the query wrote, a pattern read at or right of the factor it reads or crossing a declaration, a sentinel read of an undeclared name. The operational refusals -- a read past budget, a matcher on an unguarded body, a `<=>` that never settles, a noncharacter at the boundary -- are L2's. The floor never rejects, so every rejection is an interpretation refusing a scope, never an expression failing to denote.
- Emptiness is not an error: a query denoting the empty universe matches nothing and says so. Meaningless stays legal; whether to warn is a later layer's taste.

## North star

The layer's witness is a bubble sort: sentinels mask each line, factor reads and back-references spell the adjacent out-of-order pair, and `<=>` iterates the swap to a fixpoint, the sentinels clearing at exit. It takes decimals of any magnitude at any padding and re-emits each at the width it arrived -- `where`'s canonical binding makes the cut a value cut whatever padding the read hit wearing, and `padfree` hangs every padding on one entry, so no width cap stands in for value order:

```text
sentinel start
sentinel end

uni c      = {@char,!{\n}}
uni line   = {@c,&@c}
uni d      = {0..9}
uni digits = {@d,&@d}

{@line} => "{{@start}}{{$}}{{@end}}"
{@start,\,}{@digits}{\,}{0..9}[below 0..$2 padfree]{@end,\,} <=> "{{$1}}{{$4}},{{$2}}{{$5}}"
```

It carries no measure: it iterates until a pass finds no adjacent inversion left to swap, settling at the sorted line. What has to hold is that each swap *moves* the document -- strictly reorders a pair, never merely re-dresses it -- or the iteration spins. The top-exclusive cut secures that: inclusive `where 0..$2` would also match a value-*equal* pair, whose swap only re-dresses or repeats the document, so `below` -- the value cut less its top endpoint (`{@lo..hi,!{@hi}}`, L3) -- matches an adjacent pair exactly when it is out of order, the value-equal band named once in the std rather than spelled at each use. Its entries wear infinitely many faces (matchable, not canonically readable), so the template reads every hit as it hit.

The program, witnessed -- one document in, its lines each sorted, the program itself fixed:

| Against | Yields | Why |
| --- | --- | --- |
| `3,1,2` | `1,2,3` | each pass swaps an adjacent inversion; iteration settles at the ascending line |
| `10,9` | `9,10` | value order, not shortlex: `9` precedes `10` though `"10"` precedes `"9"` as text |
| `09,3` | `3,09` | `where`'s value cut ignores the pad; each numeral re-emits at its arrival width |
| `007,7` | `007,7` | equal value: factor 4 strips the value-equal band, so the pair never matches to swap |
| `2,1\n4,3` | `1,2\n3,4` | the start/end sentinels mask each line, so the sort descends each line on its own |
