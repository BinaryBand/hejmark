# Himark L3 -- Standard Library (content)

<!-- Expandable layer. The floor is L1.md; the surface every entry is written over is L1_5.md. -->

<!-- cspell:words upto padfree zfold noncharacters -->

L3 is nothing but in-language declarations over the L1.5 surface: `uni` universes and `:=` definitions. No host code, no new denotation, no new registers -- every entry compiles away through L1.5's expansion into the six constructors, which is the admission test in operational form.

That admission test is also why this layer is cheap. L1 and L1.5 carry the guarantees, so they change rarely and under scrutiny; an L3 entry is just a declaration, and adding one costs what writing it costs. If a candidate entry cannot be written -- its body needs a read no register provides -- that is an L1.5 question, where a new register faces the scrutiny a new axiom does, never something to patch here.

## The std

`C` is the code-point set of the source, seeded as a bounded range minus the noncharacters -- the one `uni` the host provides. The noncharacters are L1.5's sentinel space, and subtracting them here is what keeps every `@C`-derived universe off them: `sentinel` declarations (L1_5.md) are host-seeded too, but they are per-script names, not std entries.

```text
uni hex         = {0..9,a..f}                                 -- the hex radix
uni spellings   = {{{}}, &@C}                                 -- every spelling, in shortlex
fill            := {{{}, @0}}                                 -- one entry, faced empty and zero
nonzero         := {@, !{@0}}
numerals        := {@0, {@nonzero, &@}}                       -- the value line of the head radix
shorter w       := {@spellings, !{@C^w @spellings}}           -- widths below w
upto w          := {@shorter w, @C^w}                         -- widths at most w
longer w        := {@spellings, !{@upto w}}                   -- widths above w
where lo..hi    := {@lo..hi}                                  -- the value line cut by value
pad w..w'       := {@fill^{w'} _, !{@shorter w}, !{@longer w'}}
zeros           := {{{}}, &@0}                                -- the zero-runs of the head, empty included
zfold           := {{@zeros}}                                 -- folded: one entry wearing every zero-run
padfree         := {@zfold _}                                 -- every entry at every zero-padding
```

`spellings` through `longer` are the width toolkit; `where` cuts the value line of the head radix by value, the value family's digit-walk making the cut exact over any radix; `pad` is two face cuts over the fill. `zeros` through `padfree` are the uncapped pad: `pad` bounds its widths because its `w'` feeds an exponent, and dropping the cap dissolves the exponent into a fold -- `zfold` is one entry of order type 1, so the product `{@zfold _}` moves nothing on the value axis and puts every zero-padding on the face axis. Matching a `padfree` result stays in scope, since membership decides it; a canonical-face read of one does not, since every entry wears infinitely many faces -- the read the bounded `pad` keeps. The derivations and the row-level ground truth live in L1_5.md -- this page only inventories what exists, and it is the inventory's home until the std ships as `.hmk` source the host loads.

## Adding an entry

- In-language only -- a new entry is a `uni` or `:=` declaration over the surface, nothing else.
- Expansion is admission -- if it expands into the six constructors, it enters; if it does not, it was never an L3 entry.
- Names are the interface -- entries reference each other by `@name`, acyclically, so any entry reads standalone by chasing declarations.

> Finish line: none -- the std grows entry by entry, and expansion is each entry's own admission test.
