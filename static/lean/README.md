# Lean 4 mechanization

The formal mechanization of the L1 floor (`docs/foundation/L1.md`), kept in lockstep with `Himark/core/`. This tree started as a Coq port target and is now the sole formal-verification tree; the original Coq development under `static/formal/` was purged once every membership-axis module had a passing Lean twin.

Build with `lake build` from this directory. Lean/Lake come from an `elan`-managed toolchain (pinned via `lean-toolchain`); the pytest gate in `tests/infrastructure/test_lean.py` runs the build when the toolchain is on PATH and skips otherwise, always enforces that no `.lean` file contains `sorry` or `axiom`, and checks every headline theorem's `#print axioms` stays within the trusted kernel base (`propext`, `Classical.choice`, `Quot.sound`).

## Scope: both axes, at two levels of concreteness

L1 has two axes. The **membership axis** -- which spellings a universe wears (`Universe.contains`) -- is pure structural set algebra, because collision moves ownership but never membership. That axis is mechanized here, completely and without user-declared axioms (see the trust note below for what "axiom-free" means in Lean), against the *real* syntax and semantics (`Syntax.lean`/`Semantics.lean`). Two theorems that live on the real semantics but go beyond bare membership also land here: the guarded settling bound (`L1/Membership/Settling.lean`) and the positive least-fixpoint theorem (`L1/Membership/Fixpoint.lean`), which together mechanize both halves of the doc's "Fixpoint on settled bodies", and the closure admission witness (`L1/Membership/Admission.lean`), which characterizes `{ab, {a}&{b}}`'s denotation exactly and proves it is not a regular language.

The **order axis** is mechanized as a sequence of self-contained abstract phases, each capturing one doc claim's mathematical content over an explicit model rather than an enumeration of the real syntax. Phase A (`L1/Order/Order.lean`) is the well-order-of-type-$\omega$ claim, proved over a genuinely finite alphabet rather than the membership axis's `Code := Nat`; see that file's header for why finiteness is load-bearing here. Phase B (`L1/Order/Positional.lean`) is the positional-value theorem: mixed radix over finite factors is an order isomorphism onto `Fin (product of the factor order types)` -- "finite factors give naturals" (the bridge `lexIndex_eq_mixedRadix` proves phase A is the constant-radix special case). Phase C (`L1/Order/Collision.lean`) is the collision-ownership rule: the lex order on `<value, face>` addresses is a well-order, so every spelling has a unique least claimant and every later claimant drops. Phase D (`L1/Order/Transfinitude.lean`) is bounded transfinitude: the closure-free floor stays below $\omega^\omega$, linear closure caps at $u \cdot \omega$, nonlinear closure's squared stages sup to exactly $\omega^\omega$, and the full order-type calculus never reaches $\varepsilon_0$. Phase E (`L1/Order/Enumeration.lean`) is first-appearance enumeration: stage-major order over $\omega$-many finite stages has type at most $\omega$ -- one limit, no continuation past it. Phase F (`L1/Order/Collapse.lean`) is "collision alone does not decide the type": the `{a..}{a..}` survivors collapse to $\omega \cdot k$ while the seam row's survivors keep $\omega^2$. `L1/Membership/Spelling.lean` still carries the shortlex order theory needed by the membership axis (`singleton_shortlexLt_iff`), unchanged. The phase files themselves stay independent of the membership axis; the two axes meet only in `L1/Bridge/` (below).

The first of the two long-deferred integrations -- the order semantics over the real syntax, an ordinal-valued `Universe.entries` enumeration tying the abstract phases to `Syntax.lean` terms -- has landed in v1 form as `L1/Bridge/Entries.lean`: `entriesType` is a total ordinal-valued entries enumeration on every `Node` (Mathlib's `List.Shortlex` is a well order even over the infinite alphabet; what needs finiteness is type $\omega$, not well-orderedness), the type-$\omega$ headlines instantiate phase A and phase E on the finite-alphabet / finite-stage fragment with the real `stage` ladder, and on the demotion row `{{{}}, &C}` the generated first-appearance order coincides with the spelling order. Its v2 extension (`L1/Bridge/Product.lean`, `L1/Bridge/Union.lean`, `L1/Bridge/Rows.lean`) lands the body-order-faithful enumeration for unions and binary products -- positional order on real split addresses, collision ownership by the least split, the union enumeration as an ordinal sum -- and the transfinite rows: the union row at $\omega + 2$, the `{b,c}{a..}` row at $\omega \cdot 2$, the seam row at $\omega^2$, the total collision collapse back to $\omega$, and the doc-literal nonempty-factor collapse at $\omega \cdot k$ with $k$ the alphabet size. What stays deferred there is narrower still and re-recorded in `docs/.TODO.md`: n-ary `Factors` positional machinery, the in-range-seam survivor analysis on real syntax, and the body-recursive within-body order (the landed orders use the spelling order within a body, the same sanctioned approximation as `entryLt`'s within-stage order). Still fully deferred is the converse half of the re-admission test (every *closure-free* universe has a regular face set -- it needs a DFA construction for shortlex windows over the code space; the witness half, which is what actually rules the compression route out, is proved in `L1/Membership/Admission.lean`).

## Files

Each `L1/**/*.lean` is a from-scratch Lean mechanization of the corresponding piece of the L1 floor (the doc comment atop each file notes the Coq module it was originally ported from, for history). The tree splits along the two axes described under Scope: `L1/Membership/` holds the real-semantics files, `L1/Order/` holds the abstract order-axis phases, and `L1/Bridge/` is the one place the axes meet.

- `lakefile.lean` -- package/library definition (`L1`).
- `L1.lean` -- root import module.

### `L1/Membership/` -- the real-semantics stack

- `L1/Membership/Spelling.lean` -- the shortlex spelling order and symbolic `Window`s. Headline: `singleton_shortlexLt_iff` (Lean analogue of Coq's `singleton_ltb_iff`), where `simp` discharges what Coq needed `orb_true_iff`/`andb_true_iff`/`Nat.ltb_lt` bookkeeping for. Also carries `shortlexLt_iff_fshortlex`, the bridge certifying this bespoke `Bool`-valued order agrees with Mathlib's `Prop`-valued `List.Shortlex (. < .)` (the relation the order axis's `fshortlex` is defined as), so the two shortlex theories cannot silently disagree on their shared domain.
- `L1/Membership/Syntax.lean` -- the six constructors as one mutual inductive (`Member`/`Node`/`Factors`), with `napp`, binder detection (`bindsb`), and the top-level shape predicates.
- `L1/Membership/Semantics.lean` -- the Prop-valued denotation: the mutual `walk`/`spells`/`fsplit`/`stage` block (compiled by well-founded recursion, so unfolding goes through the generated equation lemmas via `simp`, not `rfl`), plus `ndenote`/`denotes` and the monotonicity and stage-accumulation lemmas.
- `L1/Membership/Laws.lean` -- the compression laws (union idempotence/commutativity, difference, intersection, range compression, adjacency, fold flattening -- singleton and the doc's nested shape -- product unit and exponent zero, bare-`&` no-ops), plus the final-segment demotion law `unitClosure_generates`: the closure of the unit under a literal code-point range (`{{{}}, &C}`) wears exactly the spellings over that range, two-sided.
- `L1/Membership/Evaluator.lean` -- the Bool-valued mutual evaluator (`walkb`/`spellsb`/`fsplitb`/`stageb`, `containsb`) and its soundness headline `containsb_sound`: `containsb` true implies `denotes`.
- `L1/Membership/Settling.lean` -- the guarded settling bound, headline `guarded_settles`: on a settled body, `(exists k, stage n k s) -> stage n (length s + 1) s`. Three layers -- amp-irrelevance (a non-binder ignores the ambient `&`), locality (a settled body's walk of `s` reads its amp only at strictly shorter spellings, because the guard factor eats a character), and stabilization (strong induction on `|s|`: past stage `|s|+1` the answer stops moving). Stated over a semantic guardedness predicate (`SemSettled`). Also carries the boolean bridge `semSettled_of_settledExactb`: a strengthened checker `settledExactb` implies `SemSettled`, so `guarded_settles` applies to a boolean-checkable fragment of bodies (see the settledness note below).
- `L1/Membership/Completeness.lean` -- the reverse of `containsb_sound` and the crown two-sided membership theorem `containsb_exact`: on a fragment `cmpb` that is both sound (`sndb`) and complete, `containsb n s = true <-> denotes n s`. The mutual `cmp_member`/`cmp_node`/`cmp_factors` mirror the soundness block with the amp and accumulator relations flipped; closures cross the boolean/Prop stage boundary through the settling bound (`guarded_settles` via `semSettled_of_settledExactb` and `stage_complete_of`), and non-binder folds are pinned by an emptiness surrogate (`manifestb` certifies a nonempty body, ruling out the fold-to-unit branch).
- `L1/Membership/NorthStar.lean` -- the `docs/foundation/L1.md` north-star table at the membership level, every row: each nonempty row carries positive membership samples and a non-membership row, emptiness rows are proved empty for all spellings, and the fold-totality boundary cases (`{{z..a}}` and `{{a,!{a}}}` are the unit) are covered Prop-level where the evaluator's fold-unit surrogate diverges by design. Positive rows compute through `containsb_sound` and `native_decide` (the Lean analogue of Coq's `vm_compute`); negative and emptiness rows are proved at the Prop level -- walk refutations for the non-binder rows, closure-stage invariants (`numerals_body_headed`, `unguarded_fill_stage_tailed`, `abab_stage_even`, `btrees_stage_closed`) for the binder rows. The `{ab, {a}&{b}}` row also carries the exact-language characterization `anbn_exact` (both directions of a two-sided stage induction: every stage member is some $a^n b^n$, $n \ge 1$, and every such spelling appears by stage $n$), which the re-admission test in `Admission.lean` reuses; the length parity of `anbn_not_aab` falls out of it as a one-line corollary.
- `L1/Membership/Fixpoint.lean` -- the *positive* half of the doc's "Fixpoint on settled bodies", on the real semantics (the guarded half is `L1/Membership/Settling.lean`). Positivity (`positiveb`) is "no subtraction operand encloses an ambient `&`" read off the walk spine; a positive walk is monotone (`walk_amp_mono`) and continuous (`walk_amp_cont` -- "every constructor is continuous in a positive slot") in its amp. Headlines: `positive_fixpoint` (one more application of the body adds nothing: the closure at omega is a genuine fixpoint), `positive_least` (any prefixpoint contains the closure -- least fixpoint), and `bare_stages_agree` (the inflationary stages and the bare `Y_{k+1} = body(Y_k)` ladder have the same union).
- `L1/Membership/Admission.lean` -- the re-admission test, on the real semantics. `operand_needs_infinitely_many_removals`: finitely many entry-wise steps (each a finite symmetric difference) cannot take `{a..}` to the seam-free set `{a.., !{ {a..}{b}{a..} }}`, so the universe operand on union/subtraction is axiomatic. The exact language of `{ab, {a}&{b}}` -- *exactly* $a^n b^n$, $n \ge 1$ -- is `NorthStar.lean`'s `anbn_exact` (its natural north-star home); this file imports it. `closure_admission`: that face set is not a regular language (Myhill-Nerode: the left quotients by $a^{i+1}$ are pairwise distinct), so no closure-free arrangement reaches it and closure keeps its place as an axiom. The converse (closure-free implies regular) is the deferred half noted under Scope.

### `L1/Order/` -- the abstract order-axis phases

- `L1/Order/Order.lean` -- order axis, phase A: shortlex over a finite alphabet `Fin (m+1)` is a well-order of type $\omega$. Reuses Mathlib's `List.Shortlex` (well-foundedness and trichotomy) rather than reproving irreflexivity/transitivity/totality by hand, and proves the headline `finShortlex_type_omega0` by constructing an explicit order isomorphism (`valueRelIso`) onto `(Nat, <)`: `value` reads a spelling as a length-offset (`lenOffset`) plus a base-`(m+1)` numeral (`lexIndex`), the same mixed-radix reading the positional-value theorem over products reuses. Also states `fshortlex_iff_value_lt` next to `valueRelIso` (value order *is* shortlex order), stated once here so `Collapse.lean` reads shortlex through `value` without re-deriving it. Independent of the membership axis; `Code` stays `Nat` everywhere else.
- `L1/Order/Positional.lean` -- order axis, phase B: positional value is mixed radix over a product of finite factors. A tuple's digits (`ds`, each strictly below its factor's radix in `bs` -- Mathlib's pairwise `List.Forall2`) read as `mixedRadix bs ds`, the doc's weighted sum written by Horner recursion `d * bs.prod + ...` with `bs.prod` the weight `W_i`. Headline `positional_value_type`: `mixedRadix` is an order isomorphism (`posValueIso`) from the positionally ordered tuples (`tupleLt`, lexicographic on the digits) onto `(Fin bs.prod, <)`, so the product's order type is the natural `bs.prod` -- "finite factors give naturals," and "the order of multiplication is invisible" since that product is commutative. `lexIndex_eq_mixedRadix` ties it back to phase A's uniform radix. Independent of the membership axis, like `L1/Order/Order.lean`.
- `L1/Order/Collision.lean` -- order axis, phase C: collision ownership, the least `<value, face>` claim rule. An address is a `<value, face>` pair (`Address := Ordinal x-lex Nat`), ordered lexicographically so the ordinal value dominates and the natural face index breaks the tie; a claim configuration is a map `spell` from addresses to spellings. Headline `collision_settled`: because that lex order is a well-order, every address's spelling has a unique survivor -- the lex-least claimant owns it (`non_owner_drops` shows every other claimant sits strictly above and drops), so ownership is a well-defined function of the spelling and no spelling is claimed twice. `value_dominates`, `face_breaks_tie`, and `value_over_face` check the order resolves the doc's three documented collisions (across entries, within an entry, and cross-axis). Independent of the membership axis, like the other order-axis files.
- `L1/Order/Transfinitude.lean` -- order axis, phase D: bounded transfinitude, the ordinal ceiling. The closure-free calculus `FloorType` (naturals, $\omega$, sums, products) stays below $\omega^\omega$ (`floorType_lt_omega0_opow_omega0`); linear closure multiplies each stage by a finite on the right, so its limit caps at $u \cdot \omega$ and stays below $\omega^\omega$ (`linear_closure_le`, `linear_closure_lt_omega0_opow_omega0`); nonlinear closure squares its stage type each pass and its limit is *exactly* $\omega^\omega$ (`nonlinear_closure_sup`: the supremum of $\omega^{2^n}$); and the full calculus `L1Type` with the closure-limit rule $\omega^{\alpha \cdot \omega}$ never reaches $\varepsilon_0$ (headline `l1Type_lt_epsilon0`), because $\varepsilon_0$ is additively and multiplicatively principal and closed under $\omega^{(\cdot)}$ below itself. Also carries the doc's two product rows read off `Ordinal.type_prod_lex` (`two_blocks_type` is $\omega \cdot 2$, `seam_blocks_type` is $\omega^2$) and the Cantor-normal-form left-collapse $n \cdot \omega = \omega$ (`left_digit_collapses`, `mul_order_load_bearing`).
- `L1/Order/Enumeration.lean` -- order axis, phase E: first-appearance enumeration fits within one limit. The engine is `type_le_omega0_of_finite_predecessors`: a well order in which every element has finitely many predecessors has type at most $\omega$. Stage-major order over stage sizes `f : Nat -> Nat` (lexicographic on `(stage, in-stage index)` addresses) has exactly that property, so its type is at most $\omega$ (headline `stageMajor_type_le_omega0`) and exactly $\omega$ when new entries appear cofinally (`stageMajor_type_eq_omega0` -- the numerals row, where first-appearance order is value order).
- `L1/Order/Collapse.lean` -- order axis, phase F: collision alone does not decide the type. Over phase A's finite alphabet, product pairs of nonempty spellings are ordered `<value, value>`-lexicographically and collide on equal concatenation. For `{a..}{a..}` the least split pins the prefix to a singleton (`splitSurvives_iff`), so the survivors have type exactly $\omega \cdot (m+1)$ -- the doc's "collapses to $\omega \cdot k$, $k$ finite" (headline `cofinite_collision_collapses`). For `{b}{a..}{b}{a..}` every pair with a `b`-free first segment is its own least split (`bfree_survives`), so full $\omega$-blocks survive cofinally and the type stands at $\omega \cdot \omega$ (headline `seam_collision_survives`) -- "the seams collide, yet the type survives."

### `L1/Bridge/` -- where the two axes meet

- `L1/Bridge/Entries.lean` -- order semantics over the real syntax, v1: the ordinal-valued entries enumeration the order-axis phases are instantiated with. `Entries n` is the subtype of spellings a `Node` denotes (the Lean shape of the Python `Universe.entries` index set), `entrySpellLt` its shortlex spelling order, and `entriesType : Node -> Ordinal` that order's type -- total on every term, because Mathlib's `List.Shortlex (. < .)` is a well order even over the membership axis's infinite `Code := Nat` alphabet (well-foundedness and trichotomy of `<` are all it asks; the infinite alphabet costs type $\omega$, not well-orderedness, so this does not contradict `L1/Order/Order.lean`'s finiteness note). `firstStage` reads first appearance off `Semantics.lean`'s real stage ladder, and `entryLt` is the stage-major first-appearance order. Headlines: `entriesType_le_omega0` / `entriesType_eq_omega0` (phase A on real syntax: a finite code range caps the spelling order at $\omega$, exactly $\omega$ when the entries are infinite), `entryLt_type_le_omega0` / `entryLt_type_eq_omega0` (phase E fed by the real `stage` predicate in place of an abstract stage-size function), `unitClosure_entriesType` / `unitClosure_entryLt_type` / `unitClosure_entryLt_iff` (the demotion row `{{{}}, &C}`: both enumerations at exactly $\omega$, and the generated first-appearance order *is* the spelling order -- the order-level half of `unitClosure_generates`, with `unitClosure_entryLt_iff_shortlexLt` reading the same fact back through the evaluator's Bool order via `shortlexLt_iff_fshortlex`), and `anbn_entriesType` (the admission witness wears its entries at type $\omega$ too). `entryLt`'s within-stage order is the spelling order, provably faithful on the demotion row; the doc's union/product body order and the transfinite rows are the v2 files below.
- `L1/Bridge/Product.lean` -- binary products on real syntax, v2: positional order and collision ownership of faces. The load-bearing fact is that a `prod` wrapper never binds (`freeAmpb` detects only a literal `&` factor and never recurses into a brace factor), so `prod2 a b` is a non-binder even over binder factors like `unitClosure`, and the denotation inversion `prod2_denotes_iff` is unconditional -- `fsplit` hands each factor exactly its own `denotes`. Split addresses (`IsSplit`, the real cuts `s = p ++ q`) wear the positional order `splitLt` (lexicographic, prefix most significant), and an entry is owned by its least split (`leastSplit`). Headlines: `prod2_collision_settled` (every denoted spelling has a unique least split -- phase C's `collision_settled` with real cuts for addresses) and `prodLt_type_of_unique_splits` (with unique splits the owner order `prodLt` is the ordinal product of the factor enumerations, most significant factor on the left of the syntax and the right of the `*` -- phase B's content read off the real term).
- `L1/Bridge/Union.lean` -- unions on real syntax, v2: the body-major enumeration. The doc's "append a universe's entries, in its order, skipping any already present" lands as `unionLt`: the first body owns every spelling it denotes (`ownerRank`), first body's entries first, spelling order within a body. The inversion `denotes_napp_iff` carries the honest hypotheses (both bodies non-binders, second body subtraction-free); a binder operand enters by bracing it once more (`braced`, with `braced_denotes_iff`). Headlines: `unionLt_type` (the enumeration is the ordinal sum of the first body and the second body's unclaimed remainder, via `type_sum_lex`) and `unionLt_type_disjoint` (nothing to skip: exactly `entriesType n1 + entriesType n2`).
- `L1/Bridge/Rows.lean` -- the transfinite rows: entry types past $\omega$ on real terms, all through `prodLt`/`unionLt` with the closure range `{0, 1}` and markers `2`/`3`. Headlines: `collapseRow_prodLt_type` (the double closure's owner order collapses all the way to $\omega$ -- with the empty spelling in both factors every entry is claimed by `([], s)` and the product structure erases), `twoBlocks_prodLt_type` (the `{b,c}{a..}` north-star row at $\omega \cdot 2$), `seamRow_prodLt_type` (the seam row written two-factor with the marker closing the first block, at $\omega^2$; the in-range-seam survivor story stays with phase F's `seam_collision_survives`), `unionRow_unionLt_type` (a braced closure with a two-face tail at $\omega + 2$ -- the union enumeration continues past the limit), and `neCollapseRow_prodLt_type` (the doc-literal nonempty-factor `{a..}{a..}` collapse: splits collide everywhere, the least split pins the prefix to one code, and $\omega \cdot k$ survives with $k = 2$ the alphabet size -- phase F's `cofinite_collision_collapses` read off the real term).

## The evaluator's two documented approximations

- **Unsettled closures**: the Python raises `HimarkUnsettledError` where `containsb` answers `false` at the stage bound, so the evaluator under-approximates on unsettled bodies. Exactness on settled bodies is the **guarded settling theorem**: for guarded bodies, `(exists k, stage n k s) <-> stage n (length s + 1) s`. The hard `->` direction is proved in `L1/Membership/Settling.lean` (`guarded_settles`; the `<-` direction is stage monotonicity), so the doc's length-bounded stage and the Python `length s + 1` bound are mechanized. The two pieces that once stood between this and full evaluator exactness are now closed: the boolean bridge `semSettled_of_settledExactb` (so the settling bound applies to a boolean checker), and the crown two-sided `iff` `containsb_exact` in `L1/Membership/Completeness.lean`, which lifts soundness (`containsb_sound`) to `containsb n s = true <-> denotes n s` on the fragment `cmpb` (sound and complete, with exact-settled binders).
- **The fold unit**: denotational emptiness of a fold body is not boolean-decidable (with subtraction it is a language-difference emptiness problem), so `containsb` uses the sound surrogate "no adding member" (`addsb = false`). Divergence: `{{a, !{a}}}` is the unit in the Prop spec and in Python, but `containsb` misses its empty face. No north-star row is affected.

Because a subtraction flips soundness into completeness on its operand, these two gaps shape the soundness side condition `sndb`: closures, folds, and products are fine anywhere positive, but every subtraction operand must sit in the exact fragment (`exactb`: faces, ranges, finals, products of those, nested subtraction -- no fold, no `&`), where the evaluator is proved two-sided (`exact_correct`). Every north-star row satisfies `sndb`.

The same fold-unit gap is why the bridge to semantic settledness needs a strengthened checker rather than the evaluator's own `settledb`. `settledb` tests a guard's empty face with `!(containsb g [])`, which rides the `addsb = false` surrogate, so it reads a denotationally-empty guard like `{{a,!{a}}}` as nonempty and accepts a body that is not `SemSettled` -- the naive `settledb n = true -> SemSettled n` is simply false. `settledExactb` (proved in `L1/Membership/Settling.lean`) fixes this by pinning each guard witness to the exact fragment, where `exact_node` makes `containsb g [] = false` a genuine empty-face absence; `semSettled_of_settledExactb` is the honest bridge, and `cmpb`'s binder obligations are stated over it.

## Trust note

"Axiom-free" does not port from Coq literally: every Lean/Mathlib proof rests on the trusted kernel base above, so the honest gate is that a headline theorem's axiom set is a subset of it. The `native_decide` positive rows additionally rest on the compiled-reduction axiom (`Lean.ofReduceBool`), a distinct trust basis, and so are kept out of the honesty gate; the sound Prop-level rows and `containsb_sound` itself carry only the trusted base.
